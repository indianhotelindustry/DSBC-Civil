# DECISIONS — DSBC Civil

A concise record of the **major architectural decisions already made and in force**. This is a summary index, not the decision mechanism: governed decisions are made through ADRs ([`governance/adr/`](./governance/adr/)) and constitutional amendments ([`governance/amendments/`](./governance/amendments/)); the Constitution ([`governance/ERP_ARCHITECTURE_BIBLE.md`](./governance/ERP_ARCHITECTURE_BIBLE.md)) is the authoritative statement of each. Nothing below is new — every entry is verifiable in code or ratified documents.

| # | Decision | Substance | Where it lives |
|---|---|---|---|
| D-1 | **React 19 + TypeScript (strict) + Vite SPA** | Single-page client; pages → components → one service per Firestore collection → pure calculation libs | `src/`, `tsconfig.json`, Constitution §5 |
| D-2 | **Firebase as the platform** | Auth (Google + email/password), Cloud Firestore, Storage, Hosting; config via `VITE_FIREBASE_*` env vars only | `src/lib/firebase.ts`, `firebase.json`, DEP-3 |
| D-3 | **`firestore.rules` is the production trust boundary** | Per-collection role + status-transition enforcement; client/service validation is convenience, never enforcement | `firestore.rules`, NN-1, §8 |
| D-4 | **Server-authoritative financial operations via Cloud Functions** | Bill approve, payment release, VO approval etc. are Admin-SDK-only (“SERVER-AUTHORITATIVE, Platform Stabilization v1.1”); Express `server/` is a dev harness only; `secureApi` fails loud rather than falling back to client writes | `functions/`, `server/`, `firestore.rules` comments, DEP-1 |
| D-5 | **Ledger-first / posting-engine direction; honest derived reporting today** | Financials are currently derived-on-read from documents (pure calc libs); double-entry posting engine (chart of accounts, immutable `journalEntries`) is the chartered v1.2 core; no accounting claim before it reconciles | Constitution §10, NN-7, `src/lib/*Calcs.ts` |
| D-6 | **Partial billing / running bills against a WO ceiling** | Multiple bills per Work Order; cumulative billed amount capped by WO value (+ approved VOs); GST/retention/TDS handled per bill; overbilling guards in the service layer, unified in v1.1 | `billService`, `financialCalcs`, MODULE_AUDIT §9 |
| D-7 | **Role-based security, 8 roles, multi-stage approval** | ADMIN, SUPER_ADMIN, CEO, PROJECT_MANAGER, ACCOUNTS, PURCHASE_MANAGER, STORE_MANAGER, STORE_KEEPER; status-gated transitions (WO: PENDING→APPROVED→COMPLETED; Bill: DRAFT→VERIFIED→APPROVED→PAID; Payment: PENDING→APPROVED→RELEASED) enforced field-scoped in rules | `firestore.rules`, `src/types.ts` |
| D-8 | **Multi-company core** | `Company` with `CompanyCode` (SIPL/SHSPL) and `BusinessType` (CONSTRUCTION/HOSPITALITY); user scoping via `assignedCompanyIds`; company is chartered to become a boundary-enforced dimension (§23); future verticals are config packs, never forks (§24) | `src/lib/userAccess.ts`, `seedCompanies.ts` |
| D-9 | **Pure, co-located, tested calculation core** | Business math in pure functions under `src/lib/` with co-located Vitest suites (199 tests); services orchestrate, calcs compute | `src/lib/*Calcs.ts`, NN-16/TEST-2 |
| D-10 | **Transactional number series** | WO numbers issued by a Firestore transaction over an admin-configured series; no timestamp fallback; PM update rights diff-guarded to the counter bump only | `numberSeriesService`, `firestore.rules` `/numberSeries` |
| D-11 | **Append-only audit trail + version discipline** | `auditLogs` immutable; `appVersions` deployment log; `VERSION` = `package.json` = `appVersion.ts` (DEP-9); SemVer product line with annotated tags | `logAction`, `versionService`, `docs/GIT_STRATEGY.md` |
| D-12 | **Governance-first engineering** | Ratified constitution (25 sections, NN-1…NN-30), amendment process, mandatory ADRs for governed changes, merge gate on every PR (NN-28); *continue, don’t rewrite* (NN-19) | `governance/`, AMENDMENT-001 |
| D-13 | **Commercial identity: DSBC Civil** | Product rebranded from SIPL Work Orders with zero functional change; domain company codes SIPL/SHSPL are data, not branding, and were preserved | [`REBRANDING_REPORT.md`](./REBRANDING_REPORT.md), [`PROJECT_IDENTITY.md`](./PROJECT_IDENTITY.md) |

**How to add a decision:** write an ADR in `governance/adr/` (template provided), get it accepted per AMENDMENT-001 Article VII, then add a one-line entry here pointing to it.
